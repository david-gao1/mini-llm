# BPE（Byte Pair Encoding）原理与为何这样设计

本文说明 **BPE 在做什么**、**算法如何工作**，以及**为何在神经语言模型里普遍采用这类子词分词**；与 [m01 分词器实现说明](m01_tokenizer.md) 及 GPT-2 / `tiktoken` 的工程选择衔接。

---

## 1. 分词在解决什么问题

语言模型的输入必须是**有限词表上的离散符号**。把连续文本变成符号序列，常见几类：

| 粒度 | 优点 | 缺点 |
|------|------|------|
| **词级** | 语义直观 | 词表巨大；**未登录词（OOV）**无法表示；形态变化多的语言浪费参数 |
| **字符级** | 词表极小、无 OOV | 序列极长，长程依赖难学，计算昂贵 |
| **子词级（含 BPE）** | 词表可控；罕见词可拆成已知片段；**开放词表** | 需训练合并规则；实现比纯字符略复杂 |

**BPE 的定位**：在**字符（或字节）序列**上，通过**反复合并最频繁的符号对**，得到一组**子词单元**；编码时再用这套规则把文本切成 token id。**设计动机**是在**词表大小**、**序列长度**和**对罕见词/错拼/外语的覆盖**之间取得平衡。

---

## 2. BPE 的核心思想（直觉）

1. **从最小单元开始**：例如每个 Unicode 字符（或每个字节，见下文 GPT-2 做法）是一个符号。
2. **统计相邻符号对的出现次数**，找出**当前语料里最常见的一对**。
3. **把这一对合并成一个新符号**，并把它加入「可合并单元」集合。
4. **重复**直到达到预定的**合并次数**或**词表大小**。

结果是：高频的**多字符片段**（类似词根、词缀、常见英文片段）会变成**单个 token**；低频表达则被拆成多个子词 token。模型既不用为每个完整词占一行词表，也不会像纯字符那样把序列拉得过长。

---

## 3. 算法要点（训练阶段与编码阶段）

### 3.1 训练（学习合并规则）

给定大量文本语料：

- 初始化词表为**基础符号集**（字符表或字节 0–255）。
- 迭代：在**当前**所有分词结果上统计**相邻二元组**频率 → 合并频率最高的一对 → 记录规则「`AB → 一个合并符号`」。
- 停止条件：达到预设的**合并步数**或最终**词表大小**。

得到的**产出物**本质是：**有序合并规则列表** + **最终符号到 id 的映射**。OpenAI GPT-2 公开的是训练好的合并表与词表；**50257** 这类数字来自「基础符号 + 合并出的单元 + 特殊 token」的总规模，**不是**训练神经网络时随意设的超参，而是**分词器训练结果**的固定属性（与 [m01_tokenizer.md](m01_tokenizer.md) 中「与编码绑定」的表述一致）。

### 3.2 编码（推理时）

对**新**字符串：

- 先切成**基础符号**序列（与训练时一致的最小单元）。
- **按训练得到的合并顺序**依次尝试应用合并（通常与训练时优先级一致），直到无法再合并或达到实现定义的规则边界。
- 每个最终片段对应一个词表 id。

解码则是 id 序列 → 合并符号串 → 还原为字符串（需与 UTF-8 / 字节规则一致）。

---

## 4. 为什么这样设计（理论上的「好处」）

### 4.1 控制词表规模

神经网络的 **Embedding** 与输出层都是 `O(vocab_size)` 级参数。纯词级分词在开放域上词表会**爆炸**；BPE 用固定上限的合并次数，把**有效词表**压在几万量级（如 GPT-2 的 50257），与算力与内存匹配。

### 4.2 缓解 OOV，接近开放词表

未见过的词往往可拆成**已见过的子词**（例如 rareword → rare + word 或更细的片段），模型仍能对片段分配概率，而不是统一的 `<UNK>`。这对**生成**和**多语言、错拼、专有名词**更友好。

### 4.3 与统计规律一致

高频片段被合并成单 token，**降低平均序列长度**，等价于让模型在更粗的粒度上建模；低频细节保留在细粒度拆字里。这与**齐夫定律**下的语言统计特性相容：少数形式极高频，大量形式长尾。

### 4.4 可复现、可版本化

合并表与词表一旦固定，**同一实现**下 encode/decode **确定**，便于**多机训练、checkpoint 共享、与书本代码对齐**（本仓库选用 `tiktoken` + `gpt2` 的原因之一）。

## 5. GPT-2 / 实现上的常见变体（与本项目的关系）

原论文与 GPT-2 实现常采用 **字节级 BPE（byte-level BPE）**：在 **UTF-8 字节**上建 BPE，而不是直接在 Unicode 码点上。好处包括：

- **任意 UTF-8 文本**都可编码，不会出现「字符不在词表」的死角（与「开放域」目标一致）。
- 合并表在字节序列上学习，与多语言、符号混排更稳。

`tiktoken` 的 **`gpt2`** 编码即封装了 OpenAI 发布的 **GPT-2 BPE** 规则与词表；**`n_vocab == 50257`** 来自该发布版本的**固定词表规模**。本仓库不在此重复推导该数字，只需在工程中保持 **编码名、`vocab_size`、模型头维度** 一致，见 [m01_tokenizer.md](m01_tokenizer.md)。

---

## 6. 与其它子词方法的对比（极简）

- **WordPiece**（BERT 常用）：合并准则常基于**似然提升**而非单纯频次，思路仍是**迭代合并子词**。
- **Unigram LM** 等：从大方表出发**删减**，与 BPE「从小到大」方向不同，但目标类似：可控词表 + 子词覆盖。

课程若要求「手写 BPE」，通常指**按频次合并**的训练循环；**原理**与本文一致，**词表大小**需与 `config.json` 中 `model.vocab_size` 对齐。
