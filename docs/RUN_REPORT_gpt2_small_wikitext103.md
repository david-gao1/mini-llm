## 二、训练效果怎么样

### 2.1 模型确实在「学」

语言模型的核心任务是：**给一段话，猜下一个词**。

训练前，模型完全是瞎猜——词表有 5 万多个词，猜对的概率极低。  
训练后，模型在 WikiText 这种维基英文上**预测下一个词的能力明显变强**；下文说的「语法、常见搭配」是对这种现象的通俗说法，并非单独做过语法考试。

**这些话是怎么判断的（依据）：**

1. **训练在学什么：** 目标始终是「给前文，预测下一个 token」。优化用的交叉熵损失就是在度量「下一个真实 token 你分得有多高概率」——平均而言分得越准，loss 越低。
2. **「猜词越来越准」的直接证据：** 附录表中验证集上的 **val_loss** 从未用于梯度更新，代表「在未参与训练的维基正文切片」上的表现；它从约 **6.24**（第 2,000 步）单调下降到约 **3.31**（第 54,000 步），说明在同一评测口径下，下一步预测的误差持续变小。
3. **「语法、常见搭配」为什么是推断：** WikiText 本身是语法规整、搭配相对固定的百科体英文；loss 在验证集上下降，等价于模型更倾向给**像维基正文那样的延续**（统计意义上的合法序列）更高概率，而不是乱码或随机串词。我们**没有**跑单独的语法标注测试集；「语法、搭配」是对「学到了这种语料的统计规律」的口语化概括。
4. **生成样例（上文「生成的文字质量」一节）** 只是直观辅助，**不算**严谨评测；严谨结论只看 **val_loss 曲线与附录表**即可。

我们用 **val_loss（验证损失）** 来衡量「猜得准不准」——数字越低越好：

| 阶段 | val_loss | 通俗理解 |
|------|----------|----------|
| 完全没训练（瞎猜） | ~10.8 | 5 万个词里随便蒙 |
| 刚训练一小会儿（第 2,000 步） | 6.24 | 开始摸到一点门道 |
| 训练到一半（第 26,000 步） | 3.67 | 大约 39 个词里挑一个 |
| **训练结束（最好成绩）** | **3.31** | **大约 27 个词里挑一个** |

> **「在 27 个词里挑一个」算好吗？**  
> 对于一台笔记本电脑从零训 16 小时的课程项目来说，这是**合格且正常**的成绩。  
> OpenAI 官方的 GPT-2 Small 用了几百张专业 GPU 训练了几十天才拿到更好的成绩，我们的条件和它完全不在一个量级。

### 2.2 全程 27 次测试，**每一次都在进步**

训练过程中，每隔 2,000 步做一次验证测试。**一共测了 27 次，每次成绩都比上一次好**——从未出现倒退。这说明学习过程非常稳定和健康。

分两个阶段来看：

**第一轮（Epoch 1，步骤 2,000 → 26,000）—— 快速学习期：**

- val_loss 从 6.24 降到 3.67，降幅 **2.57**
- 模型从"完全不会"到"初步掌握英语规律"
- 这是进步最大的阶段

**第二轮（Epoch 2，步骤 28,000 → 54,000）—— 精细打磨期：**

- val_loss 从 3.63 降到 3.31，降幅 **0.32**
- 进步速度明显变慢，但**从未停下**
- 相当于学生已经掌握了基础知识，在做进一步提高

**关键发现：** 直到训练结束的最后一次测试（第 54,000 步），成绩**仍然在进步**。这意味着模型还没有"学到头"，如果继续训练，成绩还会更好。

### 2.3 没有「死记硬背」的问题

模型训练有一个常见的坏现象叫「过拟合」——就好比学生只会做做过的原题，一换题就不会了。

**怎么判断？** 比较两个成绩：
- **train_loss**（训练成绩）：模型在学过的数据上的表现
- **val_loss**（验证成绩）：模型在**从没见过**的数据上的表现

如果训练成绩特别好但验证成绩很差 → 说明在死记硬背。

**本次结果怎样？**

看附录表可以发现，两个成绩差距一直很小：

| 训练阶段 | train_loss | val_loss | 差距 |
|----------|------------|----------|------|
| 第 2,000 步 | 6.24 | 6.24 | 基本相同 |
| 第 26,000 步（第一轮结束） | 3.61 | 3.67 | 仅差 0.06 |
| 第 42,000 步 | 3.00 | 3.39 | 差 0.39 |
| 第 54,000 步（训练结束） | 3.48 | 3.31 | val 反而更好 |

结论：**本次训练没有出现过拟合**，模型学到的是通用的语言规律，不是在背训练数据。

> 对比之前的实验——上次用小数据集（WikiText-2，仅 10MB）训练 406M 大模型时，出现了明显的过拟合。本次把数据量扩大到 500MB 后，问题消除了。

### 2.4 生成的文字质量

训练结束后，给模型一个开头「The history of」，让它自己往下写：

> The history of the West . = = = Design = = = The original proposal was to replace the existing steel @-@ hulled ironclad battleships with the new dreadnoughts of the I Division . The design was intended …

**评价：**
- 语法基本正确，读起来像维基百科
- 内容有一定逻辑（在讨论军舰设计的历史）
- `= = =` 和 `@-@` 是 WikiText 数据集本身的格式标记，不是模型写错
- 已经不再是训练初期的乱码和无意义拼凑

## 三、还有哪些优化空间

本次训练结束时模型仍在进步，说明有多个方向可以让效果更好：

### 3.1 最容易做到的改进

| 方法 | 做什么 | 预期效果 | 难度 |
|------|--------|----------|------|
| **继续训练更多轮** | 把 `num_epochs` 从 2 改成 4 或 6 | val_loss 有望降到 3.1–3.2 以下 | 只改一个数字，但要多花 16-32 小时 |
| **调大学习率** | 当前峰值 0.0003，可以尝试 0.0006 | 学得更快，可能相同时间内学到更多 | 改一个数字，但设太高会导致训练不稳定 |

### 3.2 需要一点改动的改进

| 方法 | 做什么 | 预期效果 | 难度 |
|------|--------|----------|------|
| **增大批量** | 把等效 batch 从 4 增到 8 或 16 | 训练更稳定，train_loss 波动更小 | 需要增大 `gradient_accumulation_steps`，每步慢一些但总体更高效 |
| **加入学习率重启** | 训练第二轮时重新提高学习率再慢慢降 | 避免学习率太低后进步太慢 | 需要修改学习率调度器代码 |

### 3.3 效果最大但成本也最高的改进

| 方法 | 做什么 | 预期效果 | 难度 |
|------|--------|----------|------|
| **用更大模型** | 切到 GPT-2 Medium（406M 参数） | val_loss 可能降到 3.0 以下 | 需要约 2-3 天训练时间 |
| **用更多数据** | 加入 OpenWebText 等更大语料 | 学到更丰富的语言知识 | 需要下载额外数据、调整代码 |
| **换更好的硬件** | 使用 NVIDIA GPU（如 A100） | 同样的训练量只需几小时 | 需要租用云 GPU |

### 3.4 优先建议

如果只做一件事来提升效果，建议：**继续训练 2-4 轮**（修改 `num_epochs` 即可）。因为从曲线来看，模型到结束时还在进步，最简单的方法就是让它多学一会儿。

### 3.5 若想要「对话」与更广的「世界知识」

本次实验模型做的是 **维基正文上的下一词预测**，不是 **Chat 助手**：像 「hi, who are you」 这类闲聊与自我介绍，需要 **指令微调 / 对话数据**，一般不会单靠 WikiText 预训练就出现。

**世界知识**（靠谱的事实与常识）通常还依赖 **更大规模预训练**、**更多样语料**，以及可选的 **检索（RAG）**。对齐（RLHF / DPO 等）则更多影响风格与安全，而非单独替代事实来源。

**务实延展（由易到难）：** 先用商用或开源对话模型做对比 → 再在现有 checkpoint 上做小规模 **SFT** → 或加大预训练 / 加 **RAG**。

完整概念表与路线说明见 [`DOMAIN-KNOWLEDGE.md`](DOMAIN-KNOWLEDGE.md) **第 6.5 节**。

## 七、如何运行模型检验效果

本节约定：**如何加载 checkpoint、如何用英文公平检验**；**不要用中文开头误判英文维基模型的质量**。全域同类说明见 [`DOMAIN-KNOWLEDGE.md`](DOMAIN-KNOWLEDGE.md) **第 6.4 节**。

在 **`team-mini-llm`** 项目根目录执行（环境与训练相同：`uv sync` 后有 `.venv`）。

**1）用验证最优权重（与报告中的 val_loss 口径一致）**

```bash
cd /path/to/team-mini-llm

uv run python generate_from_checkpoint.py \
  --checkpoint runs/gpt2_small_wikitext103/checkpoint_best.pt \
  --prompt "The history of"
```

终端会打印**一整段英文**（默认再接写约 80 个新 token；采样带随机性，每次不完全相同）。

**2）常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `--prompt` | `The history of` | 开头文本，建议英文（与 GPT-2 BPE 一致） |
| `--max-new-tokens` | `80` | 在 prompt 后面续写多少个 token |
| `--temperature` | `0.8` | 越大越随机；设为 `0` 时为贪心解码，同样 prompt 输出固定 |
| `--top-k` | `25` | 只在概率最高的 k 个 token 里采样；设为 `0` 关闭 top-k |
| `--device` | `auto` | `cuda` / `mps` / `cpu`，与训练时一致即可 |

**3）若坚持用虚拟环境里的 Python 绝对路径（与 nohup 训练同款写法）**

```bash
"/path/to/team-mini-llm/.venv/bin/python" "/path/to/team-mini-llm/generate_from_checkpoint.py" \
  --checkpoint "/path/to/team-mini-llm/runs/gpt2_small_wikitext103/checkpoint_best.pt" \
  --prompt "Science fiction is"
```

**4）为什么中文开头常常「效果不好」？**

- **训练语料全是英文维基**：模型从来没学过「接下一句中文」这件事；你一输「你好」，它只能按英文维基文章的统计规律往后编，于是会很快拐成英文段落。
- **分词器是 GPT-2 英文 BPE**：中文会被拆成很多小段 token，和训练时见到的序列完全不同；有时还会在解码边界上出现问号方块或替换字符（Unicode U+FFFD）。
- **不算模型坏了**：用**英文**开头才能公平检验本次实验（与训练目标一致）。例如：

```bash
uv run python generate_from_checkpoint.py \
  --checkpoint runs/gpt2_small_wikitext103/checkpoint_best.pt \
  --prompt "The history of London began in"
```

- **正文里的 `8 @.@ 4`、`@-@`**：来自 WikiText **原始标注**（小数点、连字符的一种写法），模型照搬了语料风格，不是程序出错。

**说明：** checkpoint 里自带训练时的完整 `config`，脚本会据此重建 `GPTModel` 并加载 `model_state_dict`，无需再手写 `--config`。
